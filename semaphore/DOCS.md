# Semaphore UI add-on documentation

Modern UI and powerful REST API for Ansible (MIT). The add-on wraps the
official upstream image — a complete runner with ansible 13.x (venv),
terraform, opentofu, terragrunt, ssh/sshpass, git and rsync — running as an
unprivileged user. State lives in a single-file SQLite database under
`/data/semaphore`, so Home Assistant backups capture everything.

> The upstream **Pro** edition (SSO/OIDC, 2FA, runners, Vault integration,
> Terraform HTTP backend) is a separate commercial product and is **not**
> part of this add-on. The Community Edition packaged here has no feature
> nags on core automation flows.

## Getting started

1. **Optional but recommended**: set `admin_password` in the add-on options
   *before* first start.
2. Start the add-on and open the web UI at `http://<host>:3000`
   (or the configured port).
3. If you did not set `admin_password`, a random one was generated —
   read it with:

   ```bash
   cat /data/semaphore/admin_credentials.txt
   ```

   Log in with it, change it in the UI, then delete the file.
4. Create a **project**, add a **key store** entry (SSH key), an
   **inventory**, a **repository** and a **template** — then run it.

## Configuration

| Option | Default | Description |
| --- | --- | --- |
| `admin_username` | `admin` | First-run admin login name. |
| `admin_name` | `Semaphore Admin` | First-run admin display name. |
| `admin_email` | `admin@localhost` | First-run admin email. |
| `admin_password` | *(empty)* | First-run admin password. Empty → random password generated and written to `/data/semaphore/admin_credentials.txt`. Only used on first start. |
| `max_parallel_tasks` | `10` | Maximum simultaneously running tasks. |
| `non_admin_can_create_project` | `false` | Allow non-admin users to create projects. |
| `password_login_disable` | `false` | Disable password logins (**careful**: with no other auth configured this locks everyone out). |
| `email_alert` | `false` | Send task failure alerts via SMTP. |
| `email_sender` / `email_host` / `email_port` / `email_username` / `email_password` / `email_secure` | *(empty)* / `587` / `true` | SMTP settings for alerts. |
| `additional_requirements` | *(empty)* | pip requirements installed on every start (one per line) — e.g. `pyvmomi`, `dnspython`. |
| `env_vars` | `[]` | Custom environment variables (`name`/`value`) passed to the server process — e.g. `AWS_PROFILE`, `ANSIBLE_CONFIG` overrides. |

Example:

```yaml
admin_password: "changeme-first-run"
max_parallel_tasks: 5
email_alert: true
email_host: smtp.example.com
email_sender: semaphore@example.com
additional_requirements: |
  pyvmomi
  dnspython
env_vars:
  - name: ANSIBLE_HOST_KEY_CHECKING
    value: "False"
```

### Option semantics

- `admin_*` options apply **only on first run** (when the database is
  created). Afterwards change credentials inside the UI.
- All other options are re-applied on every start — the add-on manages the
  corresponding `config.json` fields.
- The access-key encryption and session cookie keys are generated by the
  first-run setup and persisted in `config.json`; rotating them would
  invalidate stored credentials/sessions, so they are left untouched.

## Data & backups

| Data | In-container path |
| --- | --- |
| SQLite database, `config.json`, `requirements.txt` | `/data/semaphore/` |
| Task working directories, cloned repositories | `/data/tmp/` |

Everything lives under `/data`, so full and partial (app-only) Home
Assistant backups include it. Copying `/data` to another host migrates the
instance.

## Remote access

The UI does not support serving under a URL subpath, so **Home Assistant
ingress is not possible**. Use one of:

- direct LAN access on the configured port;
- an Nginx Proxy Manager host (e.g. `semaphore.maschiezza.duckdns.org` →
  `http://<haos-ip>:3000`), enable *Block Common Exploits*, *Websockets
  Support*, and a certificate;
- an optional sidebar link via a Webpage dashboard
  (`Settings → Dashboards → Add dashboard`, URL = the public URL).

## Operations

- **Logs**: add-on log shows the wrapper and server output; task output is
  in the UI.
- **Upgrades**: config/database migrations run automatically; take a backup
  first (best practice for any database-backed app).
- **Playbooks** must live in a git repository (Semaphore clones them to
  `/data/tmp`); the bundled runner has ansible-core plus common collections
  — extend via `additional_requirements`.
- **Executions** run inside the add-on container as user `semaphore`
  (uid 1001) — inventory hosts must be reachable from the HAOS host network
  (default bridge; use `host` network mode via add-on settings if you need
  LAN broadcast protocols).
